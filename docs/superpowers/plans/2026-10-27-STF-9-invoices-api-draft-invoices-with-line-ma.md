## Assumptions

- No UI in this ticket: InvoicesPage.tsx exists but the ticket scopes API only.
- Single route file api/invoices.ts with method plus ?id= dispatch, matching api/entries.ts, rather than dynamic path segments.
- Only draft invoices can be edited or voided; voiding an issued invoice belongs to the issuing ticket.
- Voided invoices carry status 'voided' and deleted_at; list excludes deleted rows unless status=voided.
- Number format is prefix plus zero-padded 4 digits (INV-0001), growing past 4 digits naturally, from users.invoice_prefix and next_invoice_number added by STF-73.
- Real Postgres is unavailable (no Docker), so the row-lock concurrency test uses a fake store; SQL locking is checked by review and the orchestrator's validation.
- Totals fit the integer (int32) columns; schema bounds on quantity, unit price and line count enforce that.

## Out of scope

- Invoice PDF generation
- Issuing/sending invoices and status transitions beyond draft and voided
- Payment recording and ledger transaction creation
- Invoices UI (InvoicesPage) and client-side API wrapper
- Changing the counter or prefix settings (done in STF-73)
